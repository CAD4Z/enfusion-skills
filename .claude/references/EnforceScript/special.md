### Managed-классы и безопасность указателей

Enforce Script не имеет автоматической сборки мусора. Обычные указатели небезопасны — после `delete` другие переменные могут ссылаться на удалённую память.

Класс `Managed` решает эту проблему через soft links (слабые ссылки):
- Все переменные, ссылающиеся на Managed-объект, автоматически обнуляются при его удалении
- Все игровые объекты DayZ наследуются от `Managed`

```cpp
// Без Managed — ОПАСНО
class A
{
    void Hello() { Print("hello"); }
}

void TestA()
{
    A a1 = new A();
    A a2 = a1;         // a2 указывает на тот же объект
    delete a1;          // a1 = null
    if (a2) a2.Hello(); // КРАШ — a2 всё ещё указывает на удалённую память
}

// С Managed — безопасно
class B: Managed
{
    void Hello() { Print("hello"); }
}

void TestB()
{
    B a1 = new B();
    B a2 = a1;         // a2 указывает на тот же объект
    delete a1;          // a1 = null, a2 тоже = null (soft link)
    if (a2) a2.Hello(); // не выполнится — a2 == null
}
```

### Automatic Reference Counting (ARC)

Для Managed-классов действует подсчёт ссылок:
- Обычные C++-подобные классы — быстрые, но без автоматического управления памятью
- Managed-классы — чуть медленнее, но автоматически удаляются при обнулении счётчика

### Сильные и слабые ссылки

| Тип | Поведение |
|-----|-----------|
| **Сильная** (`ref`) | Увеличивает счётчик ссылок, держит объект живым |
| **Слабая** (по умолчанию) | Указывает на объект, но не увеличивает счётчик |

По умолчанию сильные ссылки в:
- Локальные переменные внутри функций
- Аргументы функций
- Возвращаемые значения функций

Переменные класса — **слабые** по умолчанию. Для сильной ссылки используйте `ref`:

```cpp
class Parent
{
    ref Child m_child;     // сильная ссылка — держит Child живым
}

class Child
{
    Parent m_parent;       // слабая ссылка — не держит Parent
}
```

**Оптимальная практика**: одна сильная ссылка на объект в "владельце". Это исключает циклические ссылки и гарантирует порядок удаления.

### ref с массивами

```cpp
class ExampleClass
{
    MyClassA m_A;                      // слабая ссылка
    ref MyClassA m_B;                  // сильная ссылка
    ref array<MyClassA> m_C;           // сильная → массив, массив → слабые ссылки
    ref array<ref MyClassA> m_D;       // сильная → массив, массив → сильные ссылки
    ref MyClassA m_E[10];              // статический массив сильных ссылок
}

void Example()
{
    array<MyClassA> weak = new array<MyClassA>();
    weak.Insert(new MyClassA());
    // объект удалится сразу — массив содержит слабые ссылки, никто не держит объект

    array<ref MyClassA> strong = new array<ref MyClassA>();
    strong.Insert(new MyClassA());
    // объект живёт пока существует массив
}
```

### Ключевые слова — сводка

| Ключевое слово | Описание |
|----------------|----------|
| `new` | Создание экземпляра объекта |
| `delete` | Уничтожение экземпляра (немедленно, игнорируя ref count) |
| `null` | Нулевое значение (отсутствие объекта) |
| `this` | Ссылка на текущий экземпляр объекта |
| `super` | Обращение к базовому классу |
| `thread` | Запуск функции в отдельном потоке: `thread MyFunction()` |
| `typedef` | Определение псевдонима типа |
| `return` | Выход из функции с возвратом значения |
| `autoptr` | Автоудаление объекта при выходе переменной из scope |
| `proto` | Прототип внутренней функции (C++) |
| `native` | Native call convention (C++) |
